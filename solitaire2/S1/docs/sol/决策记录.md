## ADR-002：Godot AI MCP 的可追溯复用

- 日期：2026-09-02
- 一级依据：Godot stable 官方文档要求 editor plugin 位于 `addons/`、由 `plugin.cfg` 识别并在 Plugins 中启用。
- 成熟来源：父 Git `main@6d5eaf3c6ae6f602044f5519e62f0700dae14fd1` 内已跟踪的 Godot AI 3.2.4 addon。
- 决定：不联网安装、不从旧工作树复制；只从固定 Git 对象导出 addon 和 `mcp_verify.tscn`，逐项验证一致性。
- Bootstrap 边界：插件缺失导致第一次动作无法用 MCP，因此仅授权固定 Git 对象导出和最小 `project.godot` MCP 配置；连接后所有 Godot 验证必须通过 MCP。
- 风险控制：MCP 必须返回新目标绝对路径，避免误连接旧工程。

## ADR-008：纯 Core/State/Move 分层架构（S2，2026-09-03）

- 决定人：技术总监（负责人决定延续）；记录：执行者按决定写入。
- 分层：Presentation → Application → Core；发牌供给 Application/Core 但不得依赖 Presentation。
- 数据：CardData/CardPile 为 RefCounted 纯数据；GameState 为唯一事实来源且可深拷贝；tableau/foundation 用 `Array[CardPile]`（Godot 官方 static typing 明确不支持嵌套类型数组 `Array[Array[int]]`）；rank=id%13+1、suit=id/13。
- 移动：一切对进行中状态的改变走 Move/MoveBatch + RulesEngine + MoveExecutor；执行器返回新状态与显式 applied/generated moves（含自动翻牌 FlipTableau）；非法移动类型化拒绝且零变异。
- 约束：Core 不含 Node/Control/Texture/Firebase/广告/SEO/服务器；Scene Tree 不是 GameState。
- 影响：规则/撤销/hint/autocomplete/replay 都建立在不可变状态机之上，确定性可测。

## ADR-009：2D atlas/布局策略（S2，2026-09-03）

- 决定人：技术总监；记录：执行者按决定写入。
- 卡面：不移植 Spine 运行时、不烘焙 52 张新图；legacy atlas 解析隔离在呈现基础设施，CardView 用 Control/TextureRect 组合原 `car_new_0_6`/`card-back` 等 atlas 的 AtlasTexture region（`car_new_0_6.png` 1858×1776 RGBA8888、region 148×220）；Core 永不知道纹理/atlas。
- 分辨率：base 1080×1920 竖屏、`canvas_items` + `keep_width`（Godot 对 legacy FIXED_WIDTH 固定宽设计的直接等价，多分辨率官方文档）；editor/window override 可 540×960；安全区感知的 Control 锚点。
- 产品形式：正式场景不得含 Node3D；`mcp_verify.tscn` 保持既有 MCP 基础设施夹具原样。
- 影响：旧美术直接复用、呈现层与 Core 解耦、符合 S1 ADR-005 纯 2D 决定。
