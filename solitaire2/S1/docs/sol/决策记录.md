## ADR-002：Godot AI MCP 的可追溯复用

- 日期：2026-09-02
- 一级依据：Godot stable 官方文档要求 editor plugin 位于 `addons/`、由 `plugin.cfg` 识别并在 Plugins 中启用。
- 成熟来源：父 Git `main@6d5eaf3c6ae6f602044f5519e62f0700dae14fd1` 内已跟踪的 Godot AI 3.2.4 addon。
- 决定：不联网安装、不从旧工作树复制；只从固定 Git 对象导出 addon 和 `mcp_verify.tscn`，逐项验证一致性。
- Bootstrap 边界：插件缺失导致第一次动作无法用 MCP，因此仅授权固定 Git 对象导出和最小 `project.godot` MCP 配置；连接后所有 Godot 验证必须通过 MCP。
- 风险控制：MCP 必须返回新目标绝对路径，避免误连接旧工程。

## ADR-004：WP-01 文件计数口径修正

- 日期：2026-09-02
- 事实：固定提交中的 `solitaire/addons/godot_ai/**` 实测为 267 个普通跟踪文件；`mcp_verify.tscn` 另计 1 个；目标既有 `project.godot` 不是 addon 导出文件。
- 裁定：合同原“269 个 addon 文件”系把 267 个 addon、1 个 `mcp_verify.tscn` 与 1 个 `project.godot` 混算后的组合数，现修正为 267 + 1，`project.godot` 仅做最小配置 diff。
- 基线口径：默认源文件计数排除 `.godot/**` 与 `docs/**`；`docs/.DS_Store` 属 macOS 本地元数据，不是旧 Solitaire 残留，WP-04 必须单独披露且不得计入冻结源码基线。
- 影响：仅纠正事实和证据口径，不改变阶段目标、范围、授权、依赖或验收级别。
